================================================================================
  1. PROJECT OVERVIEW
================================================================================

Aarwins is a premium tropical soft drinks brand e-commerce web application.
It sells 6 flavours of coconut-based elixir drinks in tin packaging.

  - Brand: Aarwins Soft Drinks (aarwins.softdrinks)
  - Server: Spring Boot 4.1.0-SNAPSHOT (Java 21)
  - Database: H2 (file-based, persistent) — MySQL-ready
  - Frontend: Pure HTML + Vanilla CSS + Vanilla JavaScript (no framework)
  - Deployment: Google Cloud VM (asia-south1-c), External IP: 8.231.79.255
  - Port: 8080
  - Git: https://github.com/mirrodevelopment/AARWINS.git
  - Branch: main

    - Spring Security: CSRF disabled (stateless REST API)

        /api/products/**, /api/contact/**, /api/newsletter/**
        /product/**, /product-details.html
        /collections, /collections.html
        /checkout, /checkout/**, /checkout.html
        /, /index.html, /css/**, /js/**, /images/**
    - All other routes: require authentication (future admin)

  CorsConfig.java
    - Cross-Origin Resource Sharing configuration
    - Allows frontend to call REST APIs from browser

  GlobalExceptionHandler.java
    - @ControllerAdvice
    - Catches unhandled exceptions and returns structured ApiResponseDTO errors

  7. FRONTEND ARCHITECTURE
================================================================================

  SERVING STRATEGY
  ────────────────
  Spring Boot serves all files in src/main/resources/static/ at the root URL.
  No separate frontend server — everything runs from port 8080.

  CART SYSTEM (localStorage)
  ──────────────────────────
  Key: 'aarwins_cart'
  Format: JSON array of cart items
  Item structure:
    {
      id:       Number (product ID, 1-6) or String ('sub-' + timestamp for subscriptions),
      name:     String,
      price:    Number,
      imageUrl: String (/images/tin-*.png),
      variant:  String ("330ml"),
      quantity: Number
    }

  Image Migration (auto-runs on cart.js load):
    - Syncs imageUrl for all existing cart items to latest catalog images
    - Handles: old bottle PNGs, splash images → plain tin PNGs
    - Ensures cart always shows correct images even after updates

  COUPON SYSTEM (sessionStorage)
  ──────────────────────────────
  Key: 'aarwins_coupon'
  Stores active promo code + discount value for checkout session

  PRODUCT ID MAPPING (Frontend Catalog)
  ──────────────────────────────────────

================================================================================
  9. JAVASCRIPT MODULES & WORKFLOW
================================================================================

  cart.js — Cart Management
  ──────────────────────────
  Functions:
    migrateCartImages()   — Auto-runs on load, syncs old image URLs to new tin images
    addToCart(id, qty)    — Add product to localStorage cart, open drawer, show toast
    removeFromCart(id)    — Remove item (supports both Number and String IDs)
    updateQuantity(id,qty)— Update item quantity (supports Number and String IDs)
    saveCart()            — Persist cart to localStorage, fire 'cartUpdated' event
    getCartItems()        — Return current cart array
    renderCartDrawer()    — Render HTML into #mini-cart-panel .mcp-body
    openCartDrawer()      — Show cart drawer overlay
    closeCartDrawer()     — Hide cart drawer
    applyPromoCode(code)  — Validate promo code, return discount info
    showToast(msg)        — Show bottom notification toast

  Cart Item HTML (rendered in drawer):
    - Clicking product image/name → navigates to /product/{id}
    - Minus/Plus buttons → updateQuantity()
    - Delete button → removeFromCart()
    - Subscription items use string IDs: 'sub-' + Date.now()

  aarwins.js — Global UI
  ───────────────────────

================================================================================
  13. DATA FLOW / REQUEST LIFECYCLE
================================================================================

  FRONTEND PAGE REQUEST
  ─────────────────────
  Browser → GET /collections
    → Spring ViewController.getCollectionsPage()
    → forward:/collections.html
    → Spring serves static file from /resources/static/collections.html
    → Browser renders HTML + loads CSS + loads JS
    → JS calls /api/products to load product data (with localStorage fallback)

  ADD TO CART FLOW
  ─────────────────
  User clicks "Add to Cart" button
    → JavaScript addToCart(productId, quantity)
    → Reads product from cartCatalogFallback (client-side) or API
    → Pushes item to cart[] array with tin image URL
    → saveCart() → localStorage.setItem('aarwins_cart', JSON)
    → renderCartDrawer() → Builds HTML for #mini-cart-panel
    → openCartDrawer() → Shows slide-in panel
    → showToast("Product added to cart!")

  CHECKOUT FLOW
  ─────────────
  User clicks "PROCEED TO CHECKOUT"
    → Navigates to /checkout
    → checkout.js reads cart from localStorage
    → Renders order summary (tin images, prices, GST 18%)
    → User fills delivery form + selects payment method
    → Clicks "Place Order"
    → Cart cleared from localStorage
    → Success toast/redirect

  CONTACT FORM FLOW
  ──────────────────
  User submits contact form
    → JavaScript POST /api/contact with { name, email, message }
    → ContactController → ContactService.saveMessage()
    → ContactMessage entity saved to H2 database
    → Returns 201 with success message

  NEWSLETTER FLOW
  ────────────────
  User submits email for newsletter
    → JavaScript POST /api/newsletter with { email }
    → NewsletterController → NewsletterService.subscribe()
    → Checks if email already exists in DB
    → Saves new Newsletter entity (or returns existing)
    → Returns 201 (new) or 200 (already subscribed)

  PRODUCT DETAIL PAGE FLOW
  ─────────────────────────
  Browser → GET /product/1
    → ViewController.getProductDetailsPage("1")
    → forward:/product-details.html
    → Page loads, inline JS reads URL path: /product/1
    → Fetch /api/products/1
    → On success: populate name, price, description, ingredients from API
    → On failure (API offline): use catalogFallback[1]
    → productImages[1] → load tin-splash-watermelon.png for hero
    → renderThumbnails() → thumb 0 = tin-watermelon.png, thumbs 1-3 = SVG
    → renderRecommendations() → 3 other products with tin-splash images
